# Check Now: Plugin-Based Update Checker

## Intent

`check-now` is a local-first Go CLI that observes developer tools and reports actionable updates without changing software. Executable plugins own tool-specific detection and release lookup; the host owns protocol validation, cache persistence, locking, timeouts, and presentation.

## Goals

- Print cached actionable results from a safe POSIX shell-init hook.
- Probe installed versions locally on every shell invocation and refresh stale or forced remote targets on demand.
- Support built-in Node, Bun, Deno, fnm, Codex CLI, and Claude Code checkers.
- Allow trusted local executable plugins through a versioned JSON-over-stdin/stdout protocol.
- Preserve the last valid result when refresh fails, times out, or is offline.
- Render update commands as safely quoted text and never execute them.
- Resolve built-in release targets from official sources, with Node manager-aware lookup for proven fnm/nvm installations.

## Non-goals

No remote plugin installation, automatic software changes, desktop notifications, shell evaluation, or live-network-dependent tests.

## Design

The host discovers executable `plugin.sh` files under `<id>` directories from its built-in plugin directory and configured local directories. The first configured directory wins when canonical IDs collide. Metadata must advertise both `current` and `refresh`. `current` returns local information only; `refresh` owns target discovery and may use remote APIs. The host accepts only protocol version `1`, valid JSON, a supported status, and a complete result with an RFC3339 timestamp. Plugins write diagnostics to stderr. Target, current, and dismissal-control entries are stored atomically under separate cache directories, while legacy root result files are lazily migrated as non-dismissed targets. A refresh-wide lock serializes refresh and dismissal state changes; background refreshes use a non-blocking lock so concurrent shell startups do not queue plugin work.

The shell command probes `current` synchronously, combines it with cached targets, prints only actionable `update_available` and `unknown` entries, and starts a bounded non-forced background refresh when any target is missing or stale. `dismiss <plugin-id>` stores a target fingerprint; a changed target or forced refresh clears it. The default stale interval is 24 hours and is configurable with `CHECK_NOW_STALE_INTERVAL`.

Plugins return structured `argv` only when the installation manager is confidently known. The host quotes each argument with POSIX single-quote escaping.

## Approaches considered

1. A monolithic Go checker simplifies deployment but makes tool-specific logic harder to extend independently.
2. A remote plugin registry improves discoverability but violates the local trust and no-automatic-installation requirements.
3. The selected executable-plugin protocol keeps the host small, permits shell/Go/Node implementations, and makes the trust boundary explicit.

## Constraints

- Linux and macOS; POSIX shell output.
- Go host; executable plugins may use another runtime.
- The host never executes plugin-provided update commands.
- Tests use local fake release sources and never require live network APIs.
